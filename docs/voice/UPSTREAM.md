# Politique de suivi upstream

- Ce dépôt reste un vrai **fork** de `Kieirra/murmure`, pas une copie déliée.
- Conserver `main` comme branche de référence du fork et ne pas pousser directement sur `Kieirra/murmure`.
- Qualifier les nouvelles releases upstream par comparaison, intégration contrôlée en Draft PR et CI.
- Les modifications de TTS restent compartimentées ; les changements upstream de STT ne doivent pas être bloqués inutilement.
- Jamais de fusion automatique d'une mise à jour upstream sans tests, ni de publication à travers le mécanisme de release officiel de Murmure.
